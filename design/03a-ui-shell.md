> **2026-10-20 信息架构改版（本轮唯一口径，下面旧段落里与它冲突的以本段为准）**
>
> - **底栏三项**：今日 / 课表 / 教务。「生活」「我的」不再占 Tab。
> - **左侧栏**吸收原生活页与「我的」的身份区：右滑今日页（任意 Tab）展开，
>   **主页面在前、侧栏在后**——侧栏是静态后层，主页面右移并缩到 94%、圆角与阴影随展开渐显，
>   上下露出后层；左缘始终贴齐侧栏宽度（缩放绕中心，位移补回一半收缩量）。
>   手势 = `draggable` + 20dp 方向锁 + 32dp 落定阈值 + 临界阻尼弹簧，落定后才有触感。
> - **教务 Tab**（§3.26）汇总全部教务入口，首页不再重复挂「网页」；
>   网页核对按钮收进考试、教材、学业、培养方案、实习基地、选课、学籍、教学日历
>   各业务页顶栏，统一走 `JwImportActivity` 的 Browse 模式（与课表导入同一套 WebView：
>   电脑版 / 手机版、统一认证、返回先关弹层）。未登录时就地判 JSON（`{"flag1":2}`）→
>   自动回统一认证 → 登录后自动重开原页。
> - **设置**是独立 `SettingsActivity`：主窗口不再有隐藏的「我的」路由，
>   避免返回栈 / 状态恢复与侧栏、底栏互相干扰。入口在左侧栏左下角齿轮。
> - **生活页只剩「充值宿主」**：`Routes.LIFE` 仍存在（侧栏充值落到它），但没有底栏入口。
> - **启动页**选项 = 今日 / 课表 / 教务；旧的「生活 / 我的」选择落回今日（不写回存储）。
> - 今日页底部固定区（旧 `TodayBottomDock`）已整体删除，内容全部迁入左侧栏。

**应用内悬浮球**（2026-10-13，`ui/common/FloatingBall.kt`）：主窗口三个 Tab 常驻的圆形快捷入口，
默认在**右侧偏上**（DefaultPosition = (1, 0.72)；2026-10-18 前是贴右下角 (1, 1)，实测压住生活页「缴费账单 / 用电统计 ›」与我的页「关于 ›」的箭头）、**默认开**，可在「我的 → 通用设置 → 页面与导航」关闭。单击 → 付款码页、
双击 → 扫一扫（复用「+ → 扫一扫」的车码 / 机身码 / 别家码三档分流）、长按 → 拖动，
**松手停在拖到的任意位置（不吸附边缘）**，位置用弹簧平滑跟随 / 停住。位置全局统一一份
（归一化分数，换屏 / 转屏按比例落位），渲染在壳层、**只在主窗口**——二级页是独立 `Activity`
窗口，本就看不到它。实现要点见 `.agents/rules/nav-window.md`「悬浮球」。

账号条（2026-09-23 新增，同日升级为账户卡；**2026-10-20 起整块移到左侧栏顶部**，
设置页不再有这张卡，下面关于它的一切规格以「左侧栏身份区」为准）：**无头像**，行首直接是标题行 = 姓名 + 学号
（2026-10-10 移除原 40dp 校徽圆标，见下方「校徽移除」；学号是姓名右侧的 `bodySmall`
小字、55% 透明，`alignByBaseline` 对齐；
遮罩口径 = `domain/AccountMask.maskStudentId` 唯一不变）；副行 = 班级，班级缺失时整行不显示。
**2026-09-24 起学号自副行移到姓名右侧**（用户要求），姓名缺省时标题直接退回遮罩学号、
不再在旁边重复一份；姓名过长时它先省略（`weight(1f, fill = false)`），学号不被挤掉。
数据源分工（2026-09-23 实测定案）：**姓名**来自水宝宝一卡通
`queryCard` 的持卡人 `name`（余额加载顺带落库，零额外请求）；**班级**来自教务
学籍卡片（`/jsxsd/grxx/xsxx`），在成绩导入链路顺带抓取并落 DataStore
（`profile_name` / `profile_class`）。两个来源失败都**不阻塞**主流程，
账号条自动退回纯学号显示。

**班级的抓取时机（2026-09-24 改）**：原先只在成绩导入链路顺带抓，于是刚配好账号的人
打开「我的」页只看到一串学号，得先导一次成绩才有班级。会话层能直接取页面之后
（`CasSession.fetchHtml` + `ScoreParser.parseStudentCard`），改成两个时机主动补抓：

| 时机 | 说明 |
|------|------|
| 引导第 2 步登录成功后 | 顺手抓一次（`force = true`），用户走到「完成」页时资料已就绪 |
| 「我的」页进页、班级为空时 | 闸门在 `ProfileSyncRules.shouldAttempt`：**班级为空**且**今天没试过**。抓到就不再请求；抓不到每天最多一次，不是每次进页一次（那才是白打教务） |

闸门日期落 `profile_sync_date`。失败**静默**：姓名与班级是锦上添花，不值得把「我的」页
弄成错误态，也不该打断任何主流程。

一卡通接口没有班级字段、其头像接口已下线（实测 404），账号条本就无可用头像来源
（原用校徽，2026-10-10 移除）。点眼睛图标切换完整学号仍然只在内存里展示，
不写存储不进剪贴板与日志；账号条本体不可点。

**2026-09-24（UI 规格见 §3.16，技术见 §4.27）**：本卡改为**常显**——显示条件从
「有 `YktCredentialStore` 凭证」改为「永远显示」，学号来源改成 `CredentialVault`
（CAS 与一卡通两份任取非空），缺失时标题显示「未登录」，卡内新增登录状态入口
（教务 / 一卡通 / 胖乖生活，当时是三行列表，2026-09-26 改为三格）。这样没配一卡通的
用户也有了身份区与登录入口。
实施前本节的口径仍按现状读。

**2026-09-26（UI 规格见 §3.16）**：卡内登录入口由三行列表改为**三格**，同时「开水」

**2026-10-20（四格并入账号中心）**：卡内四格（教务 / 一卡通 / 胖乖生活 / 趣智校园）删除，

**窗口转场（P6，2026-09-19）**——最简原始的右滑覆盖，不做视差/缩放：

| 场景 | 规格 |
|------|------|
| Tab 间切换 | 180ms 交叉淡入淡出——三个 Tab 平级，横向滑动会误导层级 |
| 打开二级页（SubpageActivity / JwImportActivity / TranscriptActivity） | 新窗口从右缘平移推入覆盖主窗口，280ms 减速曲线（`res/anim/slide_in_right`）；主窗口给 `res/anim/stay_still`（0→0 静止动画 = 原地不动，纯覆盖，非左右推移） |
| 关闭二级页（页内返回 / 系统返回，统一走 `finish()`） | 顶层窗口向右滑出露出主窗口，240ms 加速曲线（`res/anim/slide_out_right`）；被露出的主窗口给 `res/anim/stay_still` |

**不动的那一侧要给 `stay_still`，不能传 0**（2026-09-26 修：二级页返回没有跟手预览）：
0 的含义是「这一侧没有动画资源」，跟手预览（预测性返回）需要两侧都有可按进度驱动的
动画资源才接力得出来——传 0 时手势滑到一半没有预览、松手才切页。静止动画是 0→0 位移，
观感与传 0 完全一致。

实现分两套（`WindowTransitions.kt`，2026-09-23 起）：

| 系统 | 做法 | 效果 |
|------|------|------|
| API 34+（Android 14） | 窗口自己在 `onCreate` 调 `overrideActivityTransition` 声明 OPEN/CLOSE 过渡 | 系统把返回手势的进度交给这套动画：滑到一半能看见上一页、松手前可以撤回（预测性返回） |
| API 33 及以下 | 启动方 / 关闭方调 `overridePendingTransition`（platform 没有新机制） | 手势结束后才播过渡 |

**App 自己接管返回的页面没有系统跟手预览**：AndroidX activity 1.9.3 在 API 34+ 会把
`OnBackPressedDispatcher` 的回调注册成 `OnBackAnimationCallback`（只要该窗口有启用中的回调），
等于声明「跟手动画由 App 负责」，系统不再代为播放——而 `BackHandler` / `NavController` 的
返回栈都不提供动画。因此：

- 页内浮层若希望跟手，得自己用 `PredictiveBackHandler` 驱动动画（`DisplaySettingsOverlay`
  已按此改：面板位移 + 遮罩淡出跟着手势走，撤回弹回、松手才关）；
- 笔记/作业详情（有未保存修改时）、教务导入与成绩单（WebView 能后退时）、学工表单、
  首启引导这些**接管返回**的页面在接管生效期间没有跟手预览，这是平台行为，不是漏配；
- 底栏 Tab 之间是 NavHost 的返回栈（`NavController` 兜返回），同样没有跟手预览；
  要换成系统的跟手动画就得放弃「返回回启动页」的栈语义（回到任何 Tab 上按返回都退到桌面），
  2026-09-26 未改。

**34+ 上不要调 `overridePendingTransition`**：它是已废弃 API，调了等于告诉系统「这个 App
没适配预测性返回」，预览会被整个关掉。2026-09-23 在 Redmi K70（Android 16）上对比过：
调旧 API 时手势过程中只有边缘指示条、没有任何预览，松手才切页；换成新 API 后能看到下层
页面从左侧跟手推入。manifest 的 `android:enableOnBackInvokedCallback="true"` 是同一件事的
声明（targetSdk 34+ 本就默认开，写出来是为了表明意图，**别改成 false**）。

**二级页里拉起 App 之外的界面（微信扫一扫 / 微信支付 / 浏览器 / 快趣出行 / 系统设置页…）
一律走 `WindowTransitions.startActivityOutsideApp`**（2026-09-26 修「打开微信后页面跳动」）：
二级页声明的 OPEN 过渡 enterAnim（右推入）在本窗口**从外部应用返回**时会被系统当作
「被打开」的一侧整个重放，观感是页面凭空再滑一次。跨 task 的往返才会重放，而微信是
singleTask、永远开不进调用方的 task，所以「Activity context 不设 NEW_TASK」只救得了
浏览器、救不了微信。该出口在拉起前把本窗口的开/关过渡全部临时换成 `stay_still`，
返回过渡放完（`onWindowFocusChanged(true)`）再还原推入/滑出；只有 SubpageActivity
参与抑制——MainActivity 没有过渡覆盖，不能顺手加。

**顶栏 insets 用钉住版 `pinnedStatusBars()`（`ui/common/StableInsets.kt`）**——同一报障的
另一半根因（2026-09-26 用户复测：「打开微信瞬间顶栏突然上跳然后还原」）：跨 task 过渡期间
系统会临时改变状态栏可见状态（HyperOS 过渡动画、微信扫一扫页的沉浸式全屏），本窗口收到
statusBars 高度**瞬时归零**的 insets，贴着实时 insets 让位的顶栏就跟着上跳、还原后再回落。
钉住版**只认更大的值**（状态栏高度在窗口活着期间不会真的变小），瞬时归零与回落都不落地。
会拉起外部应用的页面必须显式传它：出码页、一卡通、缴费账单、作业详情、快捷方式、
权限设置、附近单车、今日页、生活页；不拉起外部应用的页面继续用 M3 默认/实时值。
代价：横屏这类状态栏高度真变小的形态，顶栏保留竖屏让位高度（宁可多让，不跟系统栏跳舞）。

二级页所有入口必须经 `SubpageActivity.start(...)` / `openSubpage(...)` /
`openSubpageForResult(...)` / `JwImportActivity.start(...)`，转场随这些帮助方法生效；
绕过它们直接 `startActivity` 会静默丢转场（MainActivity 曾有 3 处，已收口）。

**从桌面图标回到 App 时的页面恢复（P6，2026-09-23）**——桌面图标点击带的是
`NEW_TASK|RESET_TASK_IF_NEEDED`，四种 manifest 组合都真机跑过：

| MainActivity 配置 | 点桌面图标后发生什么 |
|------|------|
| 默认 standard | 栈顶再压一个 MainActivity，底下还压着刚才的二级页：用户看到今日页，按返回又能退回二级页 |
| standard + `alwaysRetainTaskState` | 同上（那个属性只管 task 超时被 reset 这一条路） |
| `singleTask` | 不重复压实例，但 clearTop 把二级页销毁，用户只能落在根页 |
| `singleTask` + `alwaysRetainTaskState` | 仍然 clearTop |

现行做法是**让多余的那个实例自己让位**：`MainActivity.onCreate` 开头判断
「不是 task 根 + `action=MAIN` + `category=LAUNCHER`」就直接 `finish()` 并 return
（连 `setContent` 都不走，不占一帧），系统随即把原任务栈带到前台。二级页不会被销毁，
滚动位置、地图视野、已填内容全都在——这才是「窗口保活」，恢复机制只是兜底。
`alwaysRetainTaskState="true"` 留着挡系统 30 分钟的 task reset。判据必须带
action/category：小组件点击与通知跳板都不带，它们该正常起窗口。

兜底是 `SubpageStack`（窗口链 + 活窗口门控）：只有在 ROM 真走 clearTop、页面已被销毁
（链在、活窗口为 0）时才按原参数把链补回来。链的增删只认 `SubpageActivity.onResume`
与 `finish()`——clearTop 与系统回收都不走 `finish()`，记账挂到 `onDestroy` 会被一起清掉。

通知（作业提醒、上课提醒）的 `PendingIntent` 指向 **MainActivity 跳板**而不是
`SubpageActivity`，带 `NEW_TASK|CLEAR_TASK`：指名二级页会让它在 App 未运行时成为新任务的
根，用户按返回直接退到桌面。小组件点击（整卡 / 周网格）同样走 `NEW_TASK|CLEAR_TASK`
——`SINGLE_TOP|CLEAR_TOP` 在 standard 上要 intent 与栈中实例的 baseIntent 匹配才生效，
我们那份是纯显式 intent，匹配不上，实测清不掉二级页。
