> 本文档是 [DESIGN.md](../DESIGN.md) 的拆分件。代码注释里的「DESIGN §x.y」章节号一字未改，索引见 DESIGN.md 的映射表。

## 3. 信息架构与 UI（续 · §3.14–§3.29）

### 3.14 导出成绩单（2026-09-24，P6；接口见 §4.25）

**入口**：我的 → 学习 → 成绩查询（§4.15）列表**末尾卡片**「导出带章成绩单」，
副标题写清用途「教务处电子签章 PDF · 可选学期 · 评优评先可用」。

放列表末尾而不是顶栏图标：出口与页面里的学期/学年分组**无关**（分组管的是本地成绩库的展示）；
顶栏只留「重新导入 / 成绩设置」，导出是低频动作，首屏优先给筛选、汇总与成绩明细。
卡片形态与今日页服务卡同一套语言。
同一个入口在**空态**（本地没导入过成绩）下也保留——两边数据源不同，本地为空不影响从签章系统出单。

**窗口**：独立 `TranscriptActivity`（不是 `SubpageActivity` 的二级页）。原因在 §4.25：
这一页里有一个按需出现的统一认证 WebView，转屏会销毁它，所以与教务导入窗口一样锁竖屏。

**四态流程**（学期与勾选跨态保留，失败重试不用重选）：

| 状态 | 界面 | 出口 |
|------|------|------|
| 读取中 | 水滴加载态「正在读取可选学期」 | 有 `sid` → 就绪；无 → 待登录 |
| 待登录 | 说明 + 「去登录」+ 「已经登录过了，重试」 | 授权返回 → 自动重读 |
| 就绪 | 学期多选（每项带「N 门课程」）+ 全选/全不选 + 底部「导出成绩单（N 个学期）」 | 点导出 → 出单中 |
| 出单中 | 加载态「正在生成成绩单」（服务端要跑 Excel→PDF，通常几秒） | 成功 → 完成；失败 → 失败态 |
| 完成 | 术语标签 + 文件名与体积 + 「打开 / 分享 / 存到下载」+「再导一份」 | — |
| 失败 | `InlineNoticeRow`（按异常分档）+「重试」 | 重试 → 重读 |

**默认全选**：完整成绩单是评优评先的常用形态，少勾一个学期交上去比多勾更糟。
勾选是「全选之后取消几个」的常见路径，所以两张按钮都给（全选 / 全不选）。

**授权层**：平时不出现。只有 `CookieManager` 里没有 `sid` 或已失效时才顶上来，
里面是统一认证页；落点一到签章系统域就自动收起并继续（底部另有「已登录，继续」兜底，
防页面结构变化导致自动识别失灵）。返回键先收授权层，不关整个窗口。

**结果三动作**：`打开`（系统 PDF 阅读器）、`分享`（`ACTION_SEND`）、`存到下载`（系统 SAF 选位置）。
前两个走 FileProvider 的临时授权 Uri；第三个由用户自己选目录，App 不申请任何存储权限。
文件默认只落应用私有目录，并只保留最近 10 份（§4.25）。

**最近导出**（2026-09-24 追加）：导出窗口顶栏的历史图标 → 二级页 `SubpageScreen.TRANSCRIPTS`。
列出本机保存的成绩单（学期标签 + 导出时刻 + 体积），每条支持 打开 / 分享 / 删除，顶部可清空。

- 行点击 = 打开；右侧只留 分享 与 删除 两个按钮。同一个动作不给两处入口。
- 删除与清空都要确认（成绩单删了只能重导，而重导出来的单子未必与已交出去的那份一致）。
- **定位是「最近导出」不是档案库**：页面底部写明「只保留最近 10 份，超出的下次导出自动清理，
  要长期留存请存到下载或分享出去」。所以要长期留的路径是用户自己另存，App 不做长期档案。
- 列表数据源就是目录本身，不建 Room 表也不写清单文件：不会出现「记录还在、文件没了」的分叉。
  代价是列表只能反推文件名里的信息，界面不显示成绩单的内部字段（也不需要）。

**文案里的两条实话**：卡片写明含证件照与教务处成绩专用章；就绪态底部一行小字说明
签章系统只有 HTTP 明文通道。不写这两条，用户既不知道自己拿到的是不是正式单据，
也不知道这个页面在校内网外多走一步意味着什么。

### 3.15 学工表单：宿舍报修 · 请假（2026-09-24，P6；接口与实测见 §4.26）

**入口**：我的 → 校园服务 → 「学校系统」→ 宿舍报修 / 请假。

**窗口**：独立 `XgFormActivity`，按表单标识分发（宿舍报修，以及以后加进来的任何学工表单
共用这一个窗口），锁竖屏，形式与 §3.14 的成绩单导出、§4.4 的教务导入完全一致。
同一个理由：窗口里会随时出现统一身份认证的表单，转屏销毁 WebView 等于让用户把密码重打一遍。

**加一个新的学工表单要做的事**：在 `XgUrls.FORMS` 里加一条 `XgForm`（id / 标题 / 副标题 /
表单页标识 / 审批应用 id），在 UI 层补一个图标映射。「学校系统」分组的入口与窗口标题
都按这份清单渲染，不用再写第二处。

**一页四件事都在这个窗口里完成**：填表、上传附件、提交、查看流程。App 自己不画表单，
也不代提交，跑的是学工系统官方移动页（§4.26 讲了为什么不做原生）。

**免登 + 直达**：窗口的起点是学工的统一认证入口，CAS 有会话就直接放行，不再问密码；
落到学工域后自动再进一层，把报修单打开。用户点「宿舍报修」看到的就是那张表，
不必自己在学工首页里找三层入口。

顺序不能反：报修单本身匿名可访问，它的登录引导指向超星 passport（手机号 + 学习通密码），
先开表单会被带到一套用户从没用过的账号上。所以必须**先 `/sfrz/` 建立学工会话，
再进表单页**。直达只自动做一次，用户手动回首页之后不会再被弹进表单。

**状态条**（顶栏下方一行小字，按当前域切换）：

| 当前域 | 文案 |
|--------|------|
| 统一认证 | 用学校统一身份认证登录（与教务同一个账号） |
| 报修单 | 报修单已打开，填完点页面下方的提交 |
| 学工系统其他页 | 已进入学工系统，可从右上角回到首页找报修入口 |
| 其他 | 正在打开报修单… |

**右上角「回首页」**：直达就没有网页历史可退。这张表单若被管理员改过（页面会提示
「表单信息不存在」），或者用户要去看已提交的流程，都得有路回学工首页。

**附件上传**：走系统文件选择器（既能挑相册里的照片，也能挑文件），不申请存储权限。
`WebChromeClient.onShowFileChooser` 是这条路的唯一开关，漏了它的表现是「点上传没反应」。

**返回键**：WebView 能后退就后退，退到不能再退才关窗口——报修页里会连着跳好几层
（首页 → 宿管服务 → 列表 → 表单），直接关窗口会让用户以为提交错了。

**原生进度页**（2026-10-19，§4.49）：今日页报修卡 / 收件箱办结通知 → `SubpageScreen.DORM_REPAIR`，
纯原生只读页（状态英雄卡 + 报修信息 + 审批流程 + 当前处理人）。底部「去学工报修页核对」
打开本节的 WebView；「完成并隐藏（仅本机）」只收起今日页卡片，不向学工提交任何写操作。
进度数据来自学工「个人提交记录」的只读列表（`data/approve/apps/forms/fore/user/list`），
自动检查优先用 WebView 现成的 office 会话，不额外存学工 token。

**不做的事**：不在 App 内保存报修内容的草稿，不把提交结果抄一份到本地可编辑。
表单与流程的真相在学工服务器上；（2026-10-19 补）今日页进度卡只保留一份**只读展示快照**
（`filesDir/dorm_repair.json`，含宿舍 / 故障 / 描述 / 时间，不含姓名学号），
它不是第二个真相来源，刷新失败时宁旧勿空。

### 3.16 首次配置引导与登录状态（2026-09-24 实现，2026-09-28 呈现层重构，P7；技术见 §4.27）

**为什么要有这个**（2026-09-24 复盘）：App 要四套账号才完整可用（学校统一认证 /
一卡通·缴费平台 / 胖乖生活 / 趣智校园），而首启没有任何引导——用户只能靠逐个功能撞到
「要登录」才发现缺什么。同时「我的」页账户卡只在 `YktCredentialStore` 有凭证时才渲染
（`SettingsScreen.kt` 里 `if (masked != null)` 那道判据），没配一卡通的用户
等于没有身份区，也就没有登录入口。

#### 引导窗口（`OnboardingActivity`）

独立窗口 + `screenOrientation="portrait"`，与 `JwImportActivity` / `XgFormActivity`
同一形态（第 2 步会带出统一认证表单，转屏销毁 WebView 等于让用户把密码重打一遍）。
**不进 NavHost 路由**：首启时主窗口还没建数据，且引导走完要整窗退场，
在可返回的导航图里加一步会让「返回」的语义变得可疑。

首启判定 = `onboarding_seen`（DataStore 新键，默认 false）**且**是「新安装」
（`isFreshInstall`：`lastUpdateTime - firstInstallTime < 60 秒`）。

两个条件缺一不可：**只看键**的话，老用户设备上这个键同样不存在（它是新加的键），
升级后会被凭空弹一段引导；**只看安装时间**的话，同版本重装会重复弹。
「有没有课表」不能当判据——导入过课表又清空的用户会被误判成新安装。

| 步 | 内容 | 采集 | 校验 | 失败兜底 |
|----|------|------|------|---------|
| 1 | 欢迎 + 免责声明 | 无 | 无 | 无 |
| 2 | 学校统一认证 | 学号 + 统一认证密码 | 后台走一次真实 CAS 登录（`CasSession.ensureValid`，§4.27） | ① 凭证错就地提示、**不自动重试**；② 连续 2 次失败或命中验证码页 → 切 WebView 手登一次，登录结果回灌（§4.27「双向同步」）；③ VPN/代理开着时不尝试（`JwVpnDetector` 已有），提示先关掉 |
| 3 | 一卡通 · 缴费平台共用凭证 | 学号 + 查询密码 | 复用 `CampusCardSettingsScreen.saveAndEnable` 的登录 + `queryCard` 校验 | `NeedCaptcha`(8002/8003) → 现成文案「去浏览器登录一次」（脚本绝不硬试）；安全键盘协议自检不过 → 「请更新 App」；`MultiAccount`(8001) → 提示去网页选默认账号 |
| 4 | 胖乖生活 | 手机号 + 短信验证码 **或** 粘贴 Token（二选一） | 短信：`sendCode` → `login` → 查一次余额；Token：`validateToken` 查余额 → 落盘（**先验后存**） | 验证码错误可重发（60 秒冷却，与胖乖生活页同档）；Token 校验失败什么都不落盘，直接报错；**此步可跳过**，说明写清「开水与学校账号无关，需单独登录」 |
| 5 | 趣智校园（洗澡开热水） | 手机号 + 密码（默认）/ 短信验证码 / 粘贴会话串，三选一 | 密码与验证码走 `loginByPassword` / `loginBySms`；会话串走 `QzxySessionLink.parse` → `validateSession` 查一次学校名 → `adoptSession`（**先验后存**，验不过什么都不落盘） | 验证码可重发（60 秒冷却，与趣智校园页同档）；会话串认不出时点名缺哪个字段（`missingField`），不只说「格式不对」；**此步可跳过** |
| 6 | 完成 | 无 | 无 | 列出四项状态，失败项标「未配置」，可回第 2/3/4/5 步重来 |

**第 1 步要依次过两份声明**（2026-09-27 起首启强制读满；本轮由一份拆成两份）：

| 顺序 | 弹窗 | 正文来源 | 关闭锁 |
|------|------|---------|--------|
| 1 | 用户须知 | `domain/FirstRunNotices.kt`（**只讲事实**：非官方、数据只存本机、第三方接口可能失效） | 3 秒 |
| 2 | 免责声明 | `domain/Disclaimer.kt`（与 README 同源；**法律条款与禁止事项**） | 5 秒 |

两份都由 `ui/common/NoticeDialog` 渲染，弹完一份出队一份。锁住期间确认键置灰、
点弹窗外与按返回都关不掉（`onDismissRequest` 在锁内忽略）。每份另有一枚**「不同意并退出」**
（2026-09-30 用户要求）：点了不写同意记录、不写 `onboarding_seen`，`finishAffinity`
整个应用退场——下次启动引导与声明都会再来，**进主界面的唯一路径是同意**。锁住期间
不同意键同样置灰（连拒绝都必须等读完）。**两份正文不重复**：
「严禁刷积分 / 绕过付费 / 后果自负」只在免责声明里说一次，用户须知不再抄一遍——
同一个承诺说两遍等于稀释。

**弹哪几份由落盘的同意记录决定**，不是「首启必弹」：`domain/NoticeConsent.pendingNotices`
拿 `FirstRunNotices.VERSION` 与用户同意过的版本比对，全部同意过就是空队列（重进引导不再
打扰）。改任何一句文案都要把 `VERSION` +1，否则用户不会重看新条款。确认即落盘
（版本号 + 时刻，`DisplayPrefsStore.markNoticeConsented`）——这是**事后唯一能拿出来核对的
凭据**，「锁 N 秒」本身不产生任何记录，也就没有任何证明力。
**「我的 → 关于」是老安装唯一的确认口**（2026-09-30 用户报「用户须知一直未确认」）：队列
只在引导里弹，引导键已写过的老安装永远见不到队列；从关于页打开用户须知并关掉（确认键 /
返回 / 点遮罩都算）即写当前版本的同意记录，条目上的「已确认 / 未确认」实时翻转。

**充值风险不在首启**：首启还没登录、没余额、没充过值，此刻弹等于白发；真正生效的是每个
充值入口那一次（§3.13「充值免责声明」）。「我的 → 关于」里另给一个随时可查的只读入口，
正文与入口弹的那份同源（`domain/RechargeDisclaimer.ITEMS`）。

欢迎页底部那个「查看免责声明」按钮保留，走它打开的那次**不锁**、也不写同意记录——
用户主动再看一遍不该被罚等。

**两个第三方服务排在学校账号之后**：胖乖生活（第 4 步）与趣智校园（第 5 步）都是
第三方账号，与学校体系无关。先让用户把「学号 + 密码」一次解决，再处理这两处——
插在中间会打断节奏，也会让以为「一个账号走天下」的用户困惑。

**趣智校园这一步的三种登录方式**（2026-09-27 补）：密码是默认项（验证码要等短信，
会话串要先有另一台登录过的设备），另两种通过步骤头下方的分段控件切换（2026-09-28 起，
见下方呈现层重构）。会话串的解析与「先验后存」
与趣智校园页同一套实现（`QzxySessionLink` / `QzxyRepository.validateSession`），
差别只是这里没有「导出会话串」的入口——那是调试工具里的东西，引导里只做登录。

**第 2 步为什么用原生表单收密码**，而不是把用户丢进 WebView：WebView 登录拿不到密码，
拿不到就做不了自动续登（§4.27）。这是整个方案里唯一要让用户明确知道「App 会保存密码」
的一步，文案不能含糊。

**跳过语义**：每步独立落库、独立校验；「跳过」= 不写该步凭据、不挡后续步骤。
首启全跳过也能进主界面，相关功能各自提示未配置（与现状一致）。

**启动落点**：`MainActivity.onCreate` 阻塞读一次 `onboarding_seen`（与
`resolveStartRouteBlocking` 同一模式），为 false 则 `OnboardingActivity.start(this)`
覆盖上来，主界面照常 `setContent`（引导是不透明全屏窗口，用户看不到底下）。
**不改 manifest 的 LAUNCHER 指向**：小组件点击、通知跳板的 intent 都指向
`MainActivity`，改 LAUNCHER 会把它们的落点一起改掉。

**引导唯一实例（2026-09-28 补，修「返回又见引导」）**：引导显示期间，小组件 / 通知跳板 /
桌面快捷方式仍会把 `MainActivity` 新实例叠到引导**上面**（`NEW_TASK` + 标准 launchMode
的既有行为），新实例的 `onCreate` 又会再拉一个引导——任务叠成
`[主窗口1, 引导1, 主窗口2, 引导2]`；用户完成的是上面一对，返回时露出底下没退场的
引导1 欢迎页。三条修复：① `OnboardingActivity` 记进程内活体计数
（`companion liveInstances`，onCreate/onDestroy 夹逼）；② `MainActivity.onCreate` 在
`savedInstanceState == null && liveInstances > 0` 时直接 `finish()` 退位——守卫必须排在
`SubpageStack.clear()` / `pendingRoute` 消费之前，避免将死的实例污染进程级状态；引导期间
小组件路由本来就无处可去（课表还没导入），路由丢弃可接受；③ `start()` 的 intent 带
`REORDER_TO_FRONT`，万一有活实例时提到前台复用而不是叠新的（正常路径不可达，纯兜底；
REORDER 不回传 intent，`startAtJw` 只在没有活实例的常规路径生效——而账户卡改密码入口
在活体引导遮挡期间本就不可达）。重建场景（`savedInstanceState != null`，如引导遮挡下的
深色模式切换）不走守卫，原位重建不受影响。

**返回键（2026-09-27 改）**：引导内返回 = **上一步**（顶栏左侧同时给返回箭头）。此前是
「跳过本步」往前跳，与直觉相反——想回头改一下密码只能一路跳过再重新进引导。
跳过本步仍有两条出口：顶栏「全部跳过」（2026-10-08 改：点击先出二次确认弹窗讲清后果——
写 `onboarding_seen` 收窗、账号可在「我的」补、只想跳本步用底部的「先跳过」）收整个引导，
每屏底部的「先跳过」进下一步。

**状态判定口径**（避免实现时把「凭证在不在」和「请求失败没失败」混成一个布尔）：

| 显示 | 判据 | 载体 |
|------|------|------|
| 未登录 | 该套凭证不存在 | 持久（`CredentialVault`） |
| 已登录 | 凭证存在，且无待处理的运行时失效 | 持久 + 内存 |
| 已失效 | 凭证存在，但最近一次请求被判凭证错且已停用 | 内存（`SessionStatus`） |

App 重启后「已失效」退回「已登录」是**预期行为**：凭证还在，就该继续尝试。

**老用户的网页会话要认**：升级用户没有凭证，但 WebView 里可能还留着有效的教务会话。
状态卡若只按凭证判定，会出现「卡上说未登录、点进导入却能用」的矛盾。所以
`SessionStatus` 初始化时对教务做一次**本地检查**（只读 `CookieManager`，不联网）：
读到教务域 cookie 就显示「已登录 · 网页会话」，那一行同时给「保存密码以便自动续登」
入口——把升级用户自然引到引导第 2 步。这条不算「后台主动探测」，它一个请求都不发。
真正的失效要等下一次请求被拒才重新确认——用户一用就会撞到，不会漏报。

**退出登录**：卡内**不放假退出动作**（三格各自只有一个点击面），退出都在落点页里：

退出图标（2026-09-27 起带二次确认，见 §3.4）。语义一致 = 清该套凭据 + 清该平台
token + 状态回「未登录」，与 §4.27
「改动面」那张表的清除口径一致。

**失效之后怎么恢复**（2026-09-24 补，2026-09-26 校）：三格都指向原生账户页，
看得到状态也找得到改密码的地方，因此不做状态分流。

| 格 | 已登录 | 未登录 / 已失效 |
|----|--------|----------------|
| 教务 | 教务账户页（`JW_ACCOUNT`：学籍信息 + 更新账号密码 + 导入课表/成绩 + 导出成绩单） | 同上。**导入页只能手登 WebView，改不了已保存的密码**，账户页里才有「更新账号密码」（内部走 `OnboardingActivity.start(startAtJw = true)`）。与「一卡通」点进去是原生页保持一致 |
| 一卡通 | 校园卡设置页 | 同上（那一页本来就有凭证输入与真实登录校验） |
| 胖乖生活 | 胖乖生活页 | 胖乖生活页（手机号 + 验证码） |

**胖乖生活这一档的限制，如实记下**：它的会话是自己的 token，失效时服务端返回什么
没有实测样本，所以 App **无法在本地判定它失效**：账户卡这一格与「校园服务」条目的
副标题都按「token 在不在」显示，订阅的是仓库的登录态流（§3.4），登录/退出实时反映。
真失效了会在胖乖生活页报错，用户在那里重新收短信。这与「胖乖生活没有密码可存、
只能短信验证」是同一个根因（§4.27），不是遗漏。

#### 「登录状态已失效」的口径

**只有续登失败（凭证错）才提示失效。** 会话过期但凭证有效 → 静默续登，不打扰用户。
两者混在一起，用户会被无意义的提示淹没，真正的密码错误反而失去信号。

提示形式：状态卡该格转 `error` 色 + 一次通知（新 channel `login_state`，见 §4.27）。
用户点进去更新密码后状态回「已登录」，失败计数清零。

### 3.17 学业完成情况（2026-09-27，P6；接口与自动导入见 §4.29）

看的是**培养方案的达成度**：要求多少学分、修了多少、还差多少、哪几门没过。与成绩查询
（§4.15）互补——成绩只记「已经出了分」的课，这里还含「修读中」「未修读」和学分缺口。

入口：「我的 → 学习 → 学业完成情况」，副标题实时显示总账（`已修 104 / 161 学分 · 还需 32.8`）。

| 元素 | 内容 |
|------|------|
| 页首 | 培养方案名（如「2024 xxx专业培养方案及教学计划」）；教务没给就整行不显示 |
| 维度 chips | 课程体系 / 课程性质 / 课程属性 / 公选课类别，横向可滚。四个维度是**同一批课程的不同切法**，不是四份数据；选中项只存内存，退出重进回到默认的「课程体系」 |
| 汇总卡 | 要求学分 / 已修学分 / 正修读 / 还需学分四个数字 + 进度条（已修 ÷ 要求，夹在 0–100%）+ 一行「已修 X / 要求 Y 学分（Z%）」。要求为 0 的维度不画进度条。**「正修读」从明细现算**（`修读中` 的学分和，按课程编号去重）——教务的分组块只给「已修 / 还需」两个数，那个数只在顶层汇总表里，不这么算这一格会永远是 0（实测 24.25，与教务合计行一致） |
| 分组卡 | 默认**收起**。头行 = 分组名 + 结论标签（已达成 / 未达成 / 无结论）+ 展开箭头；副行 = 「已修 57.5 / 要求 58.5 · 还需 0.8 · 34 门」，缺项自动省略。**点击区只覆盖头行 + 副行**，不覆盖展开出来的明细。展开先给前 8 门（`GROUP_PREVIEW_COUNT`），其余折成一行「显示其余 N 门」——实测最长一组 66 门，一次铺开几千 dp，动画和视线都跟不上 |
| 课程行 | 课程名 + 副行「学期 · 属性 · 学分 · 成绩」+ 右侧修读状态（已修读 / 修读中 / 未修读）。计划外的课在副行标注。**整行可点**：弹层给全字段（课程编号 / 类别 / 属性 / 性质 / 修读情况 / 成绩 / 计划性质 / 是否学位课 / 备注），空值行不显示（教务有些维度整列不输出） |
| 列表头 | 「N 个分组 · M 门课」+ 右侧「全部展开 / 全部收起」——课程体系维度一个分组就有 34 门，想通读一遍逐个点开太累 |
| 搜索 | 顶栏搜索图标切换。打开即聚焦输入框，按**课程名或课程编号**在当前维度内过滤（忽略大小写），命中的分组强制展开、没命中的整组隐藏；顶栏图标变关闭按钮，再点一次清空并恢复 |
| 页脚 | 「数据来自教务『学业达成情况』，仅供参考；以教务处正式单据为准」 |

**为什么汇总不用教务的进度条百分比**：教务在「已修远超要求」时给过 `17200.0%` 这种值，
照抄只会让人怀疑眼睛。进度条自己按学分算，原文那个百分比只留在库里备查。
**展开与收起的交互**（照笔记库折叠分组的口径，§3.11）：

- 明细用 `AnimatedVisibility` 铺开 / 收拢：`expandVertically + fadeIn` 250ms、
  `shrinkVertically + fadeOut` 200ms（展开慢一档、收起快一档）；此前是 `if (expanded)` 瞬现瞬灭
- 头行的箭头用 `animateFloatAsState` 转 180°，与上面同一组时长——瞬变会让人怀疑自己点没点上，
  尤其明细还要 250ms 才铺开
- **展开时只滚最小必要距离**（`animateScrollBy`）：卡片下方剩不下半屏时才往上滚刚好补足的那点，
  上限是卡片自身贴到视口顶部（再滚卡片就跑出屏幕了）；剩余空间够就地展开，位置感不被打断。
  此前是 `animateScrollToItem` 直接顶到顶部、与 250ms 展开动画叠着跑——卡片先「跳」上去、
  内容再从下方刷出来，点击的位置和内容出现的位置对不上。改用 `scrollBy` 滚固定距离，
  也不会追着还在变高的卡片抖
- 汇总卡的进度条同样用 `animateFloatAsState`（600ms）平滑到目标值，首次进页与切维度都看得出在动；
  旁边的文字用目标值，免得数字跟着动画一路跳
- 整卡与明细行都有触感（走全局开关，§3.12）；无障碍标签分别是「展开 / 收起 <分组名>」与
  「查看 <课程名> 的详细信息」，箭头图标本身 `contentDescription = null`——它是装饰，
  操作语义由整卡承担
- **点击区锁在头行**：整卡可点的话，涟漪半径按**按下那一刻**的卡片高度算——收起时按 70dp 算出
  一个小圆，卡片紧接着展开成几千 dp，那个圆就停在原地盖不满，看着是一团突兀的灰色
  （用户报的正是这个）。锁在头行后点击区高度固定，涟漪铺得匀；顺带免掉「在明细里滚动误触收起」
- 明细弹层走 `ImeAwareModalBottomSheet`（与全 App 其余弹层同一套退场时序，§3.13）——
  虽然这里没有输入框，但退场动画与圆角规格不必另起一套

空态与刷新：没数据时给「正在从教务获取…」或空态 + 「重新导入」按钮，并把上次失败的原因
显示出来（「还没保存统一认证账号」「密码连续错误」这类是用户能自己解决的信息）。
顶栏右上角是「重新导入」，走 §4.29 的 OkHttp 直抓；抓取中显示转圈**与 `2/4` 这样的进度**（四个页面串行要几秒，只转圈会让人怀疑卡住），空态文案同样带进度。

**自动导入是默认体验**：首启引导登录成功、冷启动过闸门（7 天）时会自己抓，通常打开本页
已经有内容。手动刷新只是兜底。

**面板的手感与出口**（2026-10-02；用水中/待核对块 2026-10-09 与页面合并成一份实现
`WateringStatusBlock`，两个出口不再各写一套）：`QzxyEntrySheet` 与趣智校园页的状态卡
形态与分支优先级一致（未登录 / 待机 / 进行中 / 用水中 / 待核对 / 结算 / 失败），本轮补上四处：

- **关面板走退场动画**：各出口（去登录、完成结算、失败详情里的去诊断页）都走
  `rememberSheetDismisser` 的 `dismiss(after)`，先播完 `hide()` 再落 `show = false`，
  最后才执行跳页。此前是 `onDismiss()` 直接置 false，弹层从组合里被瞬间抽掉，
  表现是"啪"地消失（口径见 `.agents/rules/ui-common.md`）。「完成」的顺序要留神：
  先关面板再清 `lastSettlement`，清在前会让面板在滑走的路上变回待机态，白闪一下。
- **状态切换是动画**：状态区一个 `AnimatedContent`（`fadeIn(200)` + `fadeOut(120)`，
  与页面同一组时长），待机一个按钮到用水中六行不再硬切。高度过渡只靠
  `AnimatedContent` 自带的尺寸动画——面板**不设** `heightIn` 下限（2026-10-04 收口，
  见下）；趣智页的状态卡保留 `heightIn(min = 112.dp)`，那边垫的是整页内容。
  余额文案（读取中 → 真值）另有一条 180ms 的淡入淡出。
- **面板没有「打开趣智校园页」按钮**（2026-10-04，用户拍板「多余」）：整卡本体
  （`AppCardRow onClick = onOpen`）就是趣智页入口，点余额开面板、点卡身开页面，
  两个入口分工清晰；面板底部那行全宽按钮删掉。同轮修「弹窗下方空白过多」：
  面板状态区取消 `heightIn(min = 112.dp)` 下限——待机态内容约 72dp，垫到 112
  会在主动作下方留出一截空白。
- **用水中给徽标**：胶囊「用水中」加一枚呼吸的圆点（`rememberInfiniteTransition`，
  只改透明度、走 `graphicsLayer` 的 lambda 形式，不触发重组），右侧写「开始于 HH:mm」，
  计时用 `displaySmall` 等宽数字。这是面板里唯一的常驻动画。
- **失败态补齐两个出口**：与页面失败卡同款，「清除设备记录」（`state.selected != null`
  才可用）与「详情」。详情复用页面那个 `FailedDetailDialog`（改 `internal`），
  「去诊断页」经今日页新增的 `onOpenQzxyDebug` 直达 `SubpageScreen.QZXY_DEBUG`，
  并带上当前设备地址。
- **触感**：开始、结束、清除、标记已结束按下各给一次 `tap()`；开阀成功（用水中出现）
  与结算完成各给一次 `success()`。后两个只在面板打开之后「从无到有」的那一帧触发，
  用水中点卡片进来只是看一眼，那时不震。

状态卡的形态（`QzxyScreen.kt` 的 `StatusCard`，分支顺序即优先级）：

| 状态 | 主按钮 | 其余 |
|------|--------|------|
| 待机 | 开始用水 | 没主动选过设备就用上次那台（`openValveFromCard`） |
| 进行中 | 禁用 | 显示当前步骤：连接 / 读状态 / 下单 / 下发 |
| 用水中 | 结束用水 | 计时 + 服务端预扣金额 + 「水已经停了，标记为已结束」 |
| 待核对 | 结算核对 | 预扣金额 + 资金去向说明（见下）+ 失败时补「清除设备记录（放弃上报）」出口 |
| 结算完成 | 完成 | 本次消费金额 + 时长 + 余额，附注「金额来自服务端账单」 |

| 结束用水失败 | 重试结束用水 | 水还在流，主按钮仍是结束用水；**设备记录已保留**（失败不再清，见下） |

**「用水中」是持久化状态**（`QzxyWateringStore`）：开阀成功即登记，结束用水结算成功、
「清除设备记录」或用户手动「已到账或不再处理，清除本地记账」才清。状态走 `StateFlow`
加落盘，因为读它的有两个独立 ViewModel 实例——今日页卡片那份挂在 `MainActivity` 上，
趣智校园页与诊断页各自是二级页窗口的实例。不落盘的话退出 App 就丢，用户想不起结算，
预扣的钱一直挂着。

**记账过期不清，转「待核对」**（2026-10-09 改，原「1 小时静默清掉」作废）：
这条状态是**离线记账**，设备是不是真在放水只有问了才知道。超过 1 小时
（`QzxyWatering.EXPIRE_MILLIS`）只把**展示口径**切成「待核对」（不显示进行中的计时，
主动作变「结算核对」），记账本身留着——它是预扣去向唯一的界面痕迹，静默清掉之后
用户什么也看不到。设备真停没停由页面可见期间的**对账**回答（见下）。今日页卡片同口径
（过期不点亮整卡、副行「上次用水待核对」）；桌面小组件的 1 小时不上桌规则不变。

**用水对账与自动结算**（2026-10-09）：设备自动关停没有可预测的时刻——一直在用会用到
预扣耗尽，停手不用过一阵会自动关，开盘时点推不出来（`autoDisConTime` 语义未定论，
只进诊断文本，界面上不出现任何倒计时）。所以只在**页面 / 今日页可见（RESUMED）期间**
做反应式核对（`WateringReconcileEffect` → `reconcileWateringOnce`，30 秒一拍、与
开阀/结算共用同一把流程锁不插队、连读 3 次拿不到设备就收手、回前台复位）：
读到「消费完成，待采集」→ **自动结算**（一次前台周期内只自动发起一次，失败不自动重试，
手动「重试结算核对」还在；**开关可关**，页尾「用水设置」，默认开——关着时读到该状态
即视为终端态收手，不再轮询）；读到空闲 → 记账转「待核对」并停表。首次进页立即核对，
「后面再想起来」时不用等半分钟。

**结算失败不再清设备记录**（2026-10-09，修「事后结算只能得到『设备没有记录』」的根）：
上报被拒时设备记录**保留**——它是重试结算的唯一凭证，旧实现失败也清，等于把还能救回来的
钱一次毁掉。失败卡给双出口：重试结算（主）+「清除设备记录（放弃上报，预扣由平台处理）」。
清除成功或设备本来就没记录（空闲）时，资金口径照实说：**未结算的单在「消费记录」里先显示
¥0，平台统一处理（含退款）后才显示实际金额，一般次日到账**——客户端在记录已丢失后没有任何
上报凭证（也不该伪造），这条链路只能由平台兜底，App 负责把话说清楚并留痕（「待核对」）。
「消费记录」是长期核对渠道。

**协议状态机在 `QzxyWaterFlow`（2026-09-28 抽出；2026-10-09 成为唯一实现）**：开阀/结束/
清除的分支判定都在这里，注入假链路与假网关即可单测——状态 3 跳过停阀、停阀后「先查再等」
轮询到状态 3、清除候选命中即停、连续读不到状态提前收手、**上报失败不清设备记录**，
12 个用例钉住。`QzxyViewModel` 只保留「联网下单（签名与登记 MAC）+ 界面文案 + 登录态 +
对账驱动」，两组逻辑不再各写一份。

**记住手机号**（2026-09-28）：上次登录的手机号明文存 `QzxyDebugStore.rememberedPhone`
（密码与 `loginCode` 永远不落这里），登录成功时写入，退出登录也留着——会话失效后
重新登录少打 11 位数字。手机号不是凭证，不上加密库。

进页时用开热水页带过来的设备地址选中同一台（`focusItemId`），没有就退回上次用过的那台。
诊断文本末尾另有每次流程的阶段耗时。

**「清除设备记录」是「放弃结算」的显式出口**（2026-10-09 收口）：设备上留一条没结算的
记录，后续每次开阀都会被挡，用户必须能自己解开；而 2026-10-09 起结算失败**不再自动清**
（记录是重试的凭证），所以清除变成一个有意的选择——出现在结算失败的双出口、开阀被挡的
失败卡与诊断页工具里，文案写明「放弃上报，预扣由平台处理」。主流程的「结束用水 /

页脚免责声明：第三方非官方功能、协议来自公开逆向资料、与校方及设备厂商无关、

### 3.25 AI 调课（2026-10-07 v2 重构：单页工作单，P6；技术见 §4.39 / §4.40）

入口在**课表 hub「使用」区**（§3.3）。**一张工作单**（2026-10-07 按用户口径从对话式改版：
不做对话，简洁低调实用）：上面贴通知（文字或截图）、中间一份提案（统计 + 分组勾选 +
全宽预览）、下面一条贴底动作条；不满意就改通知再点「重新分析」。应用成功后提案卡
自动折叠成摘要卡（常驻「撤销」直达），点摘要行重新展开。
与「调课检测」完全独立——那条链是教务抓取 + 自动比对，这条链**纯手动，
用户不发送就不发任何请求**。

v2（2026-10-07，用户反馈「太乱、不统一、排版丑、交互怪」）整页重构：视觉全部收口到
项目统一件（`AppCard` 唯一卡片 / M3 按钮与分段控件 / 页面横向 16dp / 一套徽章色映射 /
软底块 / 声明类弹层用 `AlertDialog` / 全屏看图复用 `ImageViewerDialog`）；交互修复的
四个根因——① 结果就绪**不再自动折叠**（首版把勾选主战场藏了起来）；② 补上
**「重新分析」**（首版 READY 态只有「应用所选」，「改完再点分析」的回路是断的）；
③ **回执跨轮保留**（撤销入口不随新一轮分析消失）；④ 重复与假动作清零（清空 / 重试 /
撤销各只留一处；删「微调」假按钮与「已发送的通知」双份展示）。

| 交互 | 口径 |
|------|------|
| 顶栏 | 「AI 调课」+ 「调课记录」与「配置」两个入口（历史 / 设置图标）；不放「清空重来」（清空收进通知卡） |
| 通知卡 | `AppCard` 常驻第一屏：无框文本框 + 附件缩略条 + 「添加截图 / 粘贴图片 / 清空」（≥44dp 文字按钮）。卡头状态词是唯一发送状态：未分析不显示 / 已分析 · H:mm / **内容有改动**（`noticeDirty`：草稿或图集与已发送不一致）/ 分析失败。脚注写明「点「分析」前不发送任何内容 · 教师名默认脱敏」 |
| 底栏 | **唯一动作条**（与调课检测页同构：Row「TextButton 次 + Button 主」，heightIn 44dp）。逐阶段：分析（IDLE，空输入置灰）→ 停止（ANALYZING）→ 重试 + 次按钮「重新分析」（FAILED——重试 = 原样重发；输入改过时用次按钮按当前输入重跑，否则发的是旧文本）→ 应用所选（N）+ 次按钮「重新分析」（READY / UNDONE）→ 应用中…（APPLYING，事务期间整条禁用）→ **分析新通知**（APPLIED，清本轮提案回待输入，输入区与回执不动）。空结果主按钮换「重新分析」——不给死路的禁用「应用所选（0）」 |

| 读图核对 | 带图时模型复述「我读到的通知 · 请核对」；「识别有误？点这里改成文字」把识别结果填回输入框 |
| 思考过程 | 默认折叠成一行（思考中 / 思考过程 · N 字）；展开后**限高 132dp + 内部滚动 + 自动贴底** |

| 失败 | 留在卡里（不自动消失、不弹 toast、不空屏）；普通失败「去配置」，图片类失败「去掉图片重发」（截图同时从输入区移除——本会话不再自动带通知截图），已解析的条数挂一行说明（「分析未完成，不可应用」） |
| 拒收项 | 被丢弃的提议**必须可见**（「N 条提议已略过」+ 展开看原因），两类都走这里：解析失败，以及**与已生效的日期安排等价**（「该日期安排已生效，无需重复」——同一通知重发时不再列为待确认，但不静默吞）。模型给了提议但被 App 拒了时，只说「模型没有需要改动的课程」是误导 |
| 流式 | 分析中结果卡照常渲染（标题「正在分析… / 已整理 N 处改动 · 分析中」，统计条随增量更新；明细与预览在流式期间不渲染，避免半截闪烁）；还没有增量时给骨架，**绝不出现「没有改动」假结论** |
| 动效 | 结果区按段出现 / 消失（骨架 → 统计 → 明细 → 预览，淡入 + 展开 220–300ms）；折叠摘要 ↔ 展开体、思考过程展开、回执行 / 「上次应用」条出现都过动画；失败卡 ↔ 提案卡 Crossfade。统一用 `AnimatedVisibility`，不引新动画库 |
| 发送闸门 | ① 首次使用弹隐私确认（声明类走 `AlertDialog` + 统一进出场，只出现一次）；② 带图但模型未标记支持图片 → 拦一次，给「去开启图片识别」与「仍然发送」 |
| 调课记录 | `SubpageScreen.AI_HISTORY`（AI 页顶栏历史图标进）：本机留痕——每次**真正落库**记一条（零落库不算），`filesDir` JSON、上限 50 条、新在前。**撤销是栈式的**：只能撤「最新一条未撤销」，撤掉后上一条才轮到可撤；走同一条反向事务与状态闸，存档行带行 id 与自定义时间，跨会话可撤。**课表已删除的记录**永远撤不动（反向写会向不存在的课表塞孤儿行）——行上标「课表已删除」、**不挡栈**（更早的记录照常可撤），撤销前逐条核对现存课表。主页回执按 `historyId` 与该页同步（该页撤过，回主页即显示已撤销） |
| 会话生命周期 | **不落盘**（进程内）：图片目录 `ai_img/` 三条清理路径——清空输入、页面销毁（`onCleared`）、冷启动兜底，且已排除出两套备份规则；**应用留痕例外**（`ai_apply_history.json`，用户自己的操作历史，随备份走） |

**应用语义**：走 `ScheduleRepository.applyLocalChanges`——与用户**手动改课同语义**、
课表改动与日期覆盖在**同一事务**里、**不推进调课检测基线**（基线是「与教务一致的状态」，
本机改动不该动它）。指纹匹配不上（模型引用的课已被改动）的条目跳过而不是硬套，
条数在应用后写明。落库的协程跑在 `viewModelScope`（不是组合作用域）：点完立刻返回上一页
不会把写入取消掉，结果用一次性提示回吐。

**撤销**走 `ScheduleUndo.plan` 的反向事务（倒序），同样不碰基线，且带**状态闸**：
应用之后被用户手动改过的行不撤（按快照硬覆盖会静默吞掉用户的修改），条数如实报出来；
撤销按回执里记的 `timetableId` 落库——用户可能已经切了当前课表。撤销后回执留档
（`undone`）不再可撤；回执**跨轮保留**（v2），所以「重新分析」不会吞掉撤销入口。
**防重入**：判据是「**本轮**提案是否已应用」——回执带 `proposalSeq`，与当前轮对上且
未撤销才算重复。没有闸门时双击会让日期覆盖写两行、回执被覆盖成第二次的
（撤销只删得掉一份，UI 却报「已回到应用前」）。

**调课记录与跨会话撤销**（`AiApplyHistoryStore`）：每次真正落库向留痕追加一条
（存档 = 撤销所需的全部信息，含行 id 与自定义时间——它们是本机字段、不进差异指纹，
但撤销必须按 id 删 / 覆盖并原样还原）。**只有最新一条未撤销的记录可撤**，UI 与 VM
双处校验同一条判据；主页会话回执带 `historyId`，与留痕按它互相同步（记录页撤过 →
回主页 resume 即显示已撤销，不再撞指纹闸报一堆「跳过」）。

**服务配置页**（`SubpageScreen.AI_SETTINGS`，通用设置「AI」区入口，也可从 AI 页顶栏
「配置」进）：

| 项 | 口径 |
|----|------|
| 服务地址 | 预填 `https://api.deepseek.com/v1`（`AiScheduleConfig.DEFAULT_BASE_URL`），可清空自定义其它 OpenAI 兼容服务；弹层输入 |
| 模型 | 预填 `deepseek-flash`（现行官方名），可手输；弹层里「从上游获取」拉一次 `/models` 列出可选 |

| 测试连接 | 拉一次 `/models` 验证地址与 Key，成功报可用模型数 |
| 能力 · 支持图片识别 | **默认关**。探测不了（模型名用户手填、上游不给能力标记），只能显式声明；模型名看着像视觉模型时提示一句，但**不自动开**。写明 DeepSeek 官方对话模型不支持图片输入 |

### 3.26 培养方案（2026-10-07，P6；接口与自动导入见 §4.41）

**看的是培养方案的计划全量**——「哪些课安排在第几个学期上、要求多少学分」，与学业完成情况
（§3.17）互补：一个回答「计划要上什么」，一个回答「修得怎么样」。数据来自教务培养方案
「课程设置总表」，与手机端 `jiaowuh5` 里那张表同源（§4.41）。

入口：「我的 → 学习 → 培养方案」，在「学业完成情况」下面（同族相邻）。副标题实时显示
规模（`84 门课 · 共 161 学分`）；没数据时是「课程设置总表 · 从教务导入」。

| 元素 | 内容 |
|------|------|
| 页首 | 培养方案名（如「2022 xxx专业培养方案」）；教务没给就整行不显示 |
| 汇总卡 | 课程门数 / 计划学分 / 覆盖学期数三个数字（一眼的规模感） |
| 学年分组 | 大一 / 大二 / 大三 / 大四 节标题（`大一 · 27 门 · 51 学分`），只显示有课的学年与学期 |
| 学期卡 | 每学期一张卡：头行「第 N 学期 · 大一下」+ 右侧「13 门 · 27.25 学分」+ 展开箭头。**默认收起**：8 张卡头即一份培养方案目录（同学业完成情况的折叠心智），点开看该学期课程明细。展开 / 收起用 250 / 200ms 的 `AnimatedVisibility`（展开慢一档、收起快一档）+ 箭头同步旋转——瞬变会让人怀疑自己点没点上；展开时只滚最小必要距离（同 §3.17 的 `scrollToReveal`）；点击区锁在头行（涟漪半径按按下时的卡片高度算 + 防明细里误触，理由同 §3.17）；整卡头行有触感与「展开 / 收起」无障碍标签 |
| 课程行 | 课程名 + 副行「性质 · 属性 · 学分」+ 右侧学时摘要（优先总学时；纯实践课给「实践 2(周)」）。**整行可点**：弹层给全字段（课程编号 / 开设学期 / 性质 / 属性 / 学分 / 理论·实践·讲座·实验·总学时），空值行不显示 |
| 未标注兜底 | 开设学期解析不出的行（term=0）不进学年分组，表尾单列「未标注学期」——正常数据不出现，出现了就说明页面结构在变 |
| 页脚 | 「数据来自教务『培养方案』，开设学期为建议修读学期（计划口径），以教务处正式安排为准」 |

**「开设学期」是计划口径**：教务按培养方案建议的修读学期标注（1–8 = 大一上…大四下），
不等于实际开课/选课安排——选修课可能有弹性、个别课隔年开。UI 与文档都不把它当成
「这学期一定会开」。

空态与刷新、自动导入的口径与学业完成情况完全一致（见上节）：首启引导登录成功、冷启动
过闸门（7 天）自动抓，顶栏「重新导入」强制刷新，失败只弹给手动那次。

### 3.28 我的 · 问渠（志愿服务 · 劳动教育，2026-10-08，P6）

「劳动教育」卡指向志愿服务列表，所以一个模块覆盖两块。

**入口**（三处，都落问渠页）：
1. 生活页「问渠 · 志愿服务」整行卡（2026-10-19；与今日页「快趣出行」同款 `QuickEntryCard`），

2. 我的 → 校园服务 → **第三方账号** → 「问渠 · 志愿服务」（行尾 `已登录 / 点击登录`）——
   与胖乖 / 趣智 / U净 同列，凭证在第三方手里；
3. 我的页账号卡班级行的「志愿 N 工时」那截文字（点它进页）。

**账号卡那一行**（本功能的展示主位）：已登录时，账号卡的**班级行**变成

未登录 / 没数据时这一行照旧只有班级。工时来自本机影子（30 分钟 TTL），进页过期才后台刷一次，
失败静默保留旧值——**不做周期轮询**。

| 状态 | 页面 |
|------|------|
| 未登录 | 两个 tab：**手机号登录**（手机号 + 密码）/ **首次使用 · 忘记密码**（手机号 → 验证码 → 设密码，按钮带 5 分钟倒计时） |
| 已登录 | 见下：工时卡 → 活动列表 → 我的记录（折叠）三段 |

**已登录页两块**（2026-10-11 按提案页收口，用户报「排版布局与交互体验」）：

1. **工时行**（由整块大卡收成**一行**）：工时数 + `小时` + 星级 + 右侧 **「记录 ›」**入口。
   首屏还没有数时大字位显示 `…`，不把 0 摆成大数字（看着像工时被清了）。
   收一行的理由：原先是 ~100dp 的大卡，加上搜索框与筛选行，首屏只剩 2 张活动卡——
   而这一页的主角是活动列表。记录入口顺手从设置页下钻提到了手边（设置页那行保留）。
2. **可报名活动**（本页主内容，就是小程序「水利文化 → 劳动教育」那张表）：
   **搜索行**（输入框 + 一枚带角标的「筛选」按钮）+ **状态分段控件** + **条数·排序行**
   + 活动卡列表；**点卡片弹详情弹层**。

**列表与搜索共用一份全量快照**（2026-10-11，两轮改动同一个根因；机制见 §4.45）：
进页抓一份「平台上全部活动」的快照（**首次整份抓；之后每 30 分钟只增量抓第一页，
新活动一定在列表开头**），列表、筛选、排序、搜索都在这份数据上做。
**为什么不是服务端第一页**：用户报「选了『招募中优先』还是把旧的已结束排前面，切『招募中』
显示没有、点加载更多才有」——因为原先列表只有 20 条，而招募中只有个位数且不在第一页，
本地筛选 / 排序作用在这 20 条上就是错的。顺带把「搜索走服务端 `keyword`」也换掉了
（那个参数匹配哪些字段无法验证，「列表里看得见的活动搜不到」）。

- **进页**：首次整份抓快照（约几秒，列表区显示「正在获取全部活动…（首次需要几秒，之后走缓存）」）；
  之后每 30 分钟只增量抓第一页（1 个请求、几百毫秒，用户基本无感），30 分钟内进页零请求。
  抓完就是列表（本地筛 / 排），**没有「加载更多」**——列表本来就是全量，底部给「已到底 · 共 N 条」。
- **即输即搜**：输入 300ms 防抖（`WenquRules.SEARCH_DEBOUNCE_MS`）后自动搜；同一份快照上内存过滤，
  **不打服务端**。IME 搜索键 = 立即搜。清空检索词**回浏览列表、一个请求都不发**（快照那串留着）。
- **条数行**：左「共 N 条」（搜索模式「找到 N 条」）、有数据却被本地筛选藏掉时追
  「· 筛选隐藏 M 条」；右是当前排序档位（点它开筛选弹层）。
- **四类空态**（不许把「被筛掉了」说成「没搜到」）：正在抓快照 / **一条都没抓到**
  （「活动没抓到，下拉刷新重试」）/ 原始条数 > 0 但被本地筛选全挡掉
  （「有 N 条活动被当前筛选隐藏了」+ **「清除筛选」按钮**）/ 真没有（快照抓全时说
  「平台上没有名称 / 项目 / 单位 / 地点含这段字的活动」）。
- placeholder 与匹配字段一致：`搜索活动 / 单位 / 地点`。

**筛选与排序**（2026-10-11 改，用户报「筛选行被裁在屏外」）：

- **状态**留在页面上（高频）：4 项改 **`SingleChoiceSegmentedButtonRow` 等宽分段**
  （全部 / 招募中 / 进行中 / 已结束）——原先 5 枚横向滚动 chip 粗算约 400dp > 内容宽 328dp，
  最右边那枚（隐藏已满）被裁在屏外，「看不见的选项等于不存在」。
- **低频项收进底部弹层**（`WenquFilterSheet`）：**只看我报名的**（2026-10-11 新增，平台一直在回
  `isApply`，卡上早有「已报名」徽章却没有对应筛选）+ **隐藏已满** + **排序**三选 +
  「清除筛选」+「看 N 条」（实时反映筛选后的条数）。
- **排序三档**（`WenquRules.Sort`，都在本地）：**招募中优先**（默认，`displayRank`）/
  **报名截止临近**（`closingSortKey`，用平台 `apply_end_time`，已截止与没填的排最后）/
  **最新发布**（id 降序）。平台的顺序**既不是 id 也不是 add_time**（实测前 21 条严格降序、
  之后跳回旧 id），不排的话默认「全部」打开就是满屏已结束。**只重排不隐藏**，组内保持平台原序
  （`sortedBy` 是稳定排序）。
- **角标** = 弹层里开着几项（状态不算，它在页面上就看得见）；**条数·排序行**左写条数、右写当前
  排序档位，点它开同一个弹层。
- **三个筛选 + 排序都落盘记住**；**筛选对浏览与搜索同等生效**；把整页挡空时，空态说
  「有 N 条活动被当前筛选隐藏了」并给「清除筛选」（**不动排序**——排序不是「挡掉东西」的维度）。

**活动卡**（2026-10-11 重排，`WenquEntryCard`）：
首行 = 状态徽章（+ `isApply` 为真时的「已报名」徽章）· **名额** · **时间（右对齐）**；
第二行标题（最多两行，**搜索时命中高亮**）；第三行 `单位 · 地点`（一行）。

- 时间从 `单位 · 地点 · 时间` 那行提到首行右端——原先挤一行两行截断，长单位名先吃掉时间，

上方多一枚「预报名 · 准点自动抢」按钮（见下段；已排上则显示「已预报名 · <时刻> 自动抢
（点此取消）」）；次按钮固定 `复制活动名`，**主按钮按状态三选一**——可报名 → `报名`、

复制 / 拉起微信那类动作**先关弹层再执行**（`ImeAwareModalBottomSheet(pendingDismiss = …)`），
页面级提示才看得见。`去微信报名` 走 `startActivityOutsideApp`（微信是 singleTask，
从它返回会重放本页推入过渡），只把用户递到微信首页 + 复制活动名，**不代报名**。

**预报名（准点自动抢，2026-10-16；用户拍板，机制见 §4.45）**：活动详情弹层的
「预报名 · 准点自动抢」——用户对**单条活动**显式开启后，到点由 App 自动提交
（**全 App 唯一允许自动提交的路径**）：报名开始前 1 分钟起校准服务器时钟与状态、
开始前 15 秒起限次试发（≤30 发、每发间隔 1 秒），成功 / 没抢到都有通知；平台改过报名时间会自动顺延。
开启过 `WenquPreregConfirmDialog` 二次确认（写明活动名 / 报名时间 / 自动提交 / 可随时取消）；
主页与蹲点页的详情弹层都有入口（记录页不传），蹲点页控制卡与已排上的活动详情显示
「已预报名」状态行可取消。

**进页不重复取数**（DESIGN §4.45「进程内 TTL 缓存」）：工时 / 星级 / 活动列表各有一份
30 分钟缓存，页面进出、窗口重建都命中缓存（进页先用缓存快照同步铺上，不闪骨架屏）；
只有**下拉刷新**（`force`）才真的重取。**不做周期轮询**——第三方系统，别加后台任务。

**写操作**（2026-10-11 起）：**报名 / 取消报名**直接提交到问渠平台（DESIGN §4.45），
详情弹层底部动作行的主按钮按状态三选一（报名 / 取消报名 / 去微信报名），两个写操作都**先过二次确认**、
失败原因留在弹层里。2026-10-16 补两条：① 报名失败是网络类错误时补一次**只读核对**
（「其实报上了」不当失败报）；② 报名还没开始的活动可**预报名**（见上段，唯一允许自动
提交的路径）。**签到、提交材料等其它写操作仍不做**，页脚与弹层都写清「请到微信小程序内完成」。

**首次设置没有密码怎么办**：平台的 `register/reset` 语义是重置密码，对**从没设过密码**的
账号实测就是创建——所以「首次使用」那条路就是它，用户设一次密码，以后纯密码登录。

### 3.29 天气提示（今日页顶栏 · 天气页，2026-10-11，P6；数据见 §4.46）

2026-10-11 用户口径：**不做通知**，天气提示就放**今日页顶栏的次标题后面**；
天气句点那行进天气页、课表句点那行进课表页（2026-10-20，按 `TodayTip.Kind` 分流）；
设置入口在「我的 → 通用设置 → 功能」；**功能默认关**。

**那行字**（`TodayViewModel.weatherLine`，`TodayTip`）：emoji + 一句话，跟在「10/20 周二 · 第 8 周」**同一行**，
用主色渲染以示可点，超出省略号收尾。文本由 `WeatherAdvice` / `ScheduleTips` 纯函数给。

- **候选句各成一条、轮换显示**（2026-10-12）：天气句与课表句不再拼一行（顶栏那一行窄，
  拼起来必被截断），改成拆成独立句、每 **5 秒**轮换一条（`TodayViewModel.ROTATE_MILLIS`）；
  只有一条时常显。顺序：快下课有雨（独占）→ 天气句 → 课表句。
- **18:00 分界**：18:00 前讲今天、18:00 起讲明天。今日页本就有的 30 秒 tick 顺带重算，
  跨过 18:00 那行字**自己换**，不用重进页面（命中仓库 30 分钟缓存时零网络）。
  tick 只在候选句**真的变了**时才重开轮换（`distinctUntilChanged`），否则每 30 秒会跳回第一条。
- **话术优先级**：正在下雨 > 雪 / 雷暴 > 有雨 > 降水概率（≥60 记得带伞 / ≥30 带把伞稳妥）>
  雾 > 紫外线（≥6 防晒）> 高温（≥33 防暑）> 低温（≤5 添衣）> 大风（≥30km/h）>
  兜底「今天多云，19~29°C」。全不命中时**报天气 + 温度区间**，不留空。
- **课表句**（`ScheduleTips`，2026-10-20 收口为「一条只讲一件事」，按优先级取第一条）：
  1. **有实验课**（`kind == Lab`，不看地点）：只出实验课句，楼名句不出；
  2. **南北楼往返跑**：该半天（上午 1–4 节 / 下午 5–8 节）**≥2 节课**、楼全解析得出
     （`教学南/北大楼`）、南北两栋都出现。两个半天都往返 → 合并成
     「上下午都得南北楼来回跑」；只有一个半天往返 → 只报那一个，
     另一个半天的信息留给课表页；
  3. **没有往返**：上下午同楼 → 「一天的课都在 X 楼」；上下午不同楼且两个半天都 ≥2 节课 →
     「上午在 X 楼，下午在 Y 楼」；只有一个半天有 ≥2 节课 → 报那半天。
  单节课 / 位置解析不出 / 不在学期内 → 整句丢弃（宁可不说，不说错）。
  早先的并列句「上午往返跑，下午都在南楼」有 24 字、顶栏放不下，且「下午都在某楼」
  对行动没有价值，已删。
- **快下课有雨**（`ScheduleTips.dismissalTipFor`）：今天、某节课距下课 ≤15 分钟、
  下课起 1 小时内有降水 → 「等会可能有雨，记得带伞哦」，**独占整行**；
  它永远看今天，与「18:00 后讲明天」无关。它依赖逐小时预报：**天气功能关着时没有这份数据，
  这条不出**（课表句照常出）。
- 功能关着 / 取不到数据时那行是 `null`：**顶栏不留空位**，也不发任何请求；
  但课表句零网络，天气关着也照出。
- **参考日天气取不到时**：天气句不出，但课表句照出（2026-10-20 修：早先会一起吞掉）。

**排版（2026-10-20 反转了 2026-10-12 的口径）**：日期用 `M/d` 短式、**恒为内容宽、不参与让位**；
提示行 `weight(1f)` 只拿日期之外的剩余宽度，超了省略号。早先反过来（提示行先拿满整行、
日期只分剩余宽度）时，截图里的日期被压成「10月…」，而 24 字的提示自己仍然截断——
两头都没救。日期是定位信息、提示是锦上添花，所以让提示截断。轮换时**交叉淡入淡出**，
首次出现加一点上浮（`AnimatedContent`），不硬切、不突然蹦出。

**为什么不做成顶栏第三行**：M3 的 `TopAppBar` 高度固定 64dp，标题区现有两行合计 44sp，
第三行到 60sp 没有余量——用户关掉「固定字体大小」跟随系统大字号时底边会被裁。
同一行渲染在**任何字号下都只是省略号**，不裁字。改回去前先想清楚这条。

**天气页**（`SubpageScreen.WEATHER`，落点 = 顶栏天气句 / 天气设置页的「查看天气」）。
2026-10-11 按主流天气页重构过一次，自上而下：

1. **顶栏副标题写地点**（「南昌 · 瑶湖校区」）：查询点是固定坐标、没有反查地名那一步，
   地点名与坐标一起写在 `WeatherApi` 的常量里；
2. **实时卡**：居中的大字温度（`displayMedium`）+ emoji 与天气 + 今日最高 / 最低；
3. **提醒卡**：今天与明天各一句（与顶栏同一套话术）；
4. **未来 24 小时**：横向滚动的小时格，当前那一格写「现在」并标主色
   （「现在」= 不晚于此刻的最后一个整点，一条都不匹配时退回第一条），
   昼夜图标走接口逐小时给的 `is_day`，降水概率 ≥30% 的数字标主色；
5. **未来 7 天**：日期（今天 / 明天 / 后天 / 周X）+ 天气 + 最低最高温 + **温度区间条**
   （条的位置 = 该日区间在整周范围里的落点，Canvas 画，最窄留一个圆点保证可见）；
6. **六格明细**：体感 · 湿度 · 风（带风向与风速）· 紫外线（值 + 档位）· 降水概率 · 日出日落；
7. **来源署名**（CC BY 4.0，不能删）。

**首屏是骨架不是空态**：骨架与成品同一套卡片与行高（行高走 `lineHeightDp`，跟随字体缩放），
数据回来直接替换、不跳。**重新进页不闪骨架**——仓库里 30 分钟缓存还在时，首帧直接铺缓存
（`WeatherRepository.peek`），只静默更新、不转指示器。

**下拉刷新**：阈值 56dp，modifier 与 `PullToRefreshDefaults.Indicator` 必须同值；
容器吃 Scaffold 的 padding（否则指示器整条轨迹藏在顶栏后）；指示器最短驻留 650ms，
免得命中缓存时「拉下来就弹回去」。只有用户真的下拉才转指示器，进页与失败重试都不转。
取不到数据时给空态 + 「重试」（**外层套可滚动容器**，指示器靠嵌套滚动接手势）；
刷新失败但手里有旧数据时**内容照旧**、只把脚注换成「刚才没刷新成功…」。

**本页关掉了触底回弹**（2026-10-11，用户报「往下滑到底部再滑会卡一下」）：Android 12+ 的
stretch 回弹由原生 `RenderNode` 实现，回弹期间内容每帧重新录制离屏图层；本页是一条约 4 屏高的
非懒加载长内容（30 多个 emoji 字形 + 十余张卡），正好是最贵的形态。用
`CompositionLocalProvider(LocalOverscrollConfiguration provides null)` 关掉——
展示型静态页的边到边回弹没有信息量。将来若要恢复回弹，先把它改成 `LazyColumn`
（图层只有一屏高）再谈。

**天气设置**（`SubpageScreen.WEATHER_SETTINGS`，通用设置「功能」节的入口行，与 AI 调课服务同构）：
开关「在今日页显示天气」（默认关）+「查看天气」+ 口径说明 + 数据来源说明。
开关关掉即从顶栏撤下那行字，不留占位。
